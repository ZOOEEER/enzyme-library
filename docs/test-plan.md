# 测试计划

本测试计划用于 Enzyme Library / 酶库 的发布前回归与日常验收。测试采用“自动化测试 + 隔离库手工验收”的组合方式：自动化测试覆盖稳定的 schema、CSV、校验和可运行的数据库逻辑；真实界面交互通过隔离测试库手工执行，避免污染生产数据。

## 1. 自动化测试

### 1.1 回归命令

在项目根目录运行：

```bash
npm run test
npm run build
npm run build:electron
```

通过标准：

- `npm run test` 无失败用例。
- `npm run build` 可完成 React/Vite 与 Electron 编译。
- `npm run build:electron` 可完成 Electron 主进程 TypeScript 编译。
- PowerShell profile 执行策略警告不作为失败，除非命令退出码非 0。

### 1.2 自动化覆盖范围

当前自动化测试重点覆盖：

- schema 与 validation：必填字段、主键唯一、外键引用、受控词 warning、结构化结果 mean/std/unit/raw data、Engineering 相对值、突变组合格式、FASTA 序列解析。
- CSV：模板导出、当前表导出、全部导出、Units 排除、hidden 字段排除、旧未知列忽略、BOM、引号、逗号、换行、空行解析。
- 数据库逻辑：在 `better-sqlite3` 与当前 Node ABI 兼容时，使用临时 SQLite 测试 upsert、delete、逐行导入语义、外键错误、Chemicals 的 formula/InChIKey 生成与重复结构拦截。

注意：开发机可能为了 Electron 运行而将 `better-sqlite3` 编译为 Electron ABI。此时 Vitest 的 Node 进程无法加载该 native module，数据库测试会自动跳过；相关场景必须在 Electron 应用中按本计划手工验收。

## 2. CSV 输入/输出测试

### 2.1 CSV 模板

| 用例 | 前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 当前表模板 | 打开任一业务表 | 点击“下载模板 CSV” | 生成当前表 CSV，表头来自当前 schema 可见字段 |
| WT 酶字段 | 打开 WT 酶/亲本酶 | 下载模板并查看表头 | 包含 `expression_purification_method`，不包含 `protein_form` |
| hidden 字段 | 打开化合物表 | 下载模板并查看表头 | 不包含 hidden 字段 |
| Units 排除 | 任意页面 | 导出全部 CSV | 不生成 `Units.csv` |

### 2.2 CSV 导入

CSV 导入真实行为：按当前表主键逐行新增或更新，不会清空整张表；未知旧列会被忽略；若某一行存在 Error，该行不会保存，但前面已经成功保存的行不会自动回滚。导入后建议运行“整库校验”。

| 用例 | 前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 新增行 | 准备含新主键的 CSV | 导入当前表 CSV | 新记录出现于列表 |
| 更新行 | CSV 中主键已存在 | 修改非主键字段后导入 | 已有记录被更新，主键不变 |
| 未知列 | CSV 包含旧列，如 `protein_form` | 导入 CSV | 未知列被忽略，不报错 |
| 错误行 | CSV 含一行必填缺失 | 导入 CSV | 弹出错误报告；错误行不保存；成功行保留 |
| 特殊字符 | CSV 单元格含逗号、双引号、换行 | 导入后再导出 | 内容可正确解析和转义 |

### 2.3 CSV 导出

| 用例 | 前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 当前表导出 | 当前表有多条记录，列表被搜索过滤 | 点击“导出当前 CSV” | 导出当前表全部记录，不受搜索和列表字段配置影响 |
| 全部导出 | 数据库有多表数据 | 点击“导出全部 CSV” | 每个参与交换的业务表生成一个 CSV，不含 Units |
| 导出后校验 | 导出 CSV 后重新导入隔离库 | 导入并运行整库校验 | 字段与引用关系符合预期 |

## 3. 表单与校验测试

所有手工表单测试均应使用隔离测试库。

### 3.1 基础记录操作

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 新增记录 | 点击“新增”，填写必填字段并保存 | 自动编号生成，记录保存成功 |
| 复制记录 | 新增模式点击“复制”，选择已有记录 | 除主键外的字段复制到草稿，保存后生成新记录 |
| 编辑记录 | 点击已有记录“编辑” | 主键编号只读，其他字段可修改 |
| 删除记录 | 点击删除并确认 | 记录从列表移除；删除基础记录后建议运行整库校验 |
| 主键实践 | 尝试为修改编号而删除重建 | 不推荐；应优先编辑非主键字段，避免引用混乱 |

### 3.2 列表字段

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 搜索当前表 | 输入编号、名称或摘要关键词 | 列表过滤匹配记录 |
| 核心/全部字段 | 切换字段模式 | 表格列随模式变化 |
| 自定义列表字段 | 打开“列表字段”，勾选字段 | 表格按选择显示 |
| 必填字段显示 | 查看字段选择面板 | 必填字段自动加粗 |
| 恢复默认 | 点击恢复默认 | 列表列恢复默认配置 |

### 3.3 约束与校验

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 必填缺失 | 保存缺少主键或核心必填字段的记录 | 返回 Error，不保存 |
| 外键缺失 | 填写不存在的 `reference_id` / `enzyme_id` 等 | 返回 Error，不保存 |
| 受控词删除后引用 | 删除某受控词但已有数据仍使用 | 整库校验给 Warning |
| 结果 mean 无 unit | 填写活性 mean 但不填 unit | 返回 Error；Engineering 的 `fold_change_mean` 例外 |
| std 单独存在 | 填写 std 但不填 mean | 返回 Error |
| std 小于 0 | 填写负数 std | 返回 Error |
| raw data 非数字 | raw data 含 `abc` | 返回 Warning |
| Engineering 相对值 | 只填 WT 或只填突变体指标值 | 返回 Error |
| Engineering fold change | 只填 `fold_change_mean` | 可保存，不要求单位 |
| 突变组合格式 | 填 `A123B/C45D` | 无格式 Warning |
| 非标准突变格式 | 填 `A123U` 或 `A123B, C45D` | 给 Warning，但不阻断保存 |

## 4. 化合物结构测试

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 手动 SMILES | 输入 `CCO` 并保存 | 生成 2D preview、formula、InChIKey |
| 重复结构 | 两个不同 compound_id 使用同一 SMILES | 第二条保存被 InChIKey 冲突拦截 |
| 默认角色编号 | 新增化合物时选择 substrate/product/cofactor/cosolvent | 编号前缀按角色建议生成 |
| 编辑角色 | 编辑已有化合物并修改默认角色 | compound_id 不被改写 |
| Ketcher 空白打开 | 点击“画板绘制（Ketcher）” | 工具栏和画布立即显示 |
| Ketcher 载入当前结构 | 表单已有 SMILES 时点击“载入当前结构” | 画板显示当前结构 |
| Ketcher 使用结构 | 修改结构后点击“使用结构” | 回填 `canonical_smiles`，预览和结构信息更新 |
| OCSR 缺环境 | 未配置 Python/Pixi/DECIMER 时载入图片识别 | 显示明确错误，不清空现有 SMILES |
| OCSR 可选真实识别 | DECIMER 可用时选择 `test/OCSR/C3H8O.png` | 返回 SMILES 草稿，并提示人工核对后保存 |

## 5. 数据持久化测试

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 设置页路径 | 打开“设置” | 显示 SQLite 数据库路径 |
| 备份数据库 | 点击备份并保存 SQLite 文件 | 生成可保存的数据库副本 |
| 恢复数据库 | 从备份 SQLite 文件恢复 | 应用重新打开恢复后的数据 |
| 切换到新库 | 点击“切换数据库文件”，选择不存在的新 `.sqlite` | 自动初始化为空库并刷新页面 |
| 切换到已有库 | 选择已有 Enzyme Library SQLite 文件 | 应用切换到该库，原库不被覆盖 |
| 拒绝非本应用库 | 选择其它应用的 SQLite 文件 | 显示错误提示，不修改该文件 |
| 恢复后校验 | 恢复或批量导入后点击“整库校验” | 显示当前数据库问题报告 |
| 隔离库测试 | 使用临时 userData 或测试前备份/恢复 | 测试不污染真实业务数据库 |
